# Relay, live sync и стабильность майнинга

## Что происходило

За 02:17—02:23 в PID 60196: 20 закрытий пиров с LOCAL_RESOURCE_LIMIT,
16 сообщений о сбое live sync, 9 переподключений Stratum и 6 Stale job.
Основной локальный источник отключений — NodeRelayService.enqueue:
Inbound relay work queue saturated. Один serial worker имел очередь 128
задач, причем каждый входящий пакет создавал отдельную задачу.

Другой дефект: LiveChainSynchronizer.messageListener реагировал на любой
headers, включая пустой ответ GETHEADERS. Это обнуляло lastSuccess и
порождало новую проверку пиров. Пустые подтверждения актуальной цепочки
создавали повторные запросы и потерю готовности к майнингу. Отказ одного
пира также обнулял успешную проверку, выполненную другим пиром.

## Исправления

- На каждого пира создан ограниченный входящий mailbox, максимум 1024
  сообщения. На общий worker ставится один drain этого пира, а не задача
  для каждого пакета. Обработка идет порциями по 16 сообщений с уступкой
  другим пирам и maintenance. Порядок сообщений пира и однопоточная
  обработка relay сохранены; данные не отбрасываются в обычном всплеске.
- Сохранены byte limits: 2 MB на пира и 16 MB суммарно. В бюджет включены
  payload и 128 байт накладных расходов на сообщение. Превышение настоящего
  лимита по-прежнему закрывает пира. При закрытии очереди очищаются и
  резервирование освобождается; закрытие соединения выполняется вне
  монитора очереди. Удалена гонка удаления нулевого счетчика по пиру.
- Пустые headers и повторное объявление подтвержденного tip не сбрасывают
  готовность. Подключение нового пира инициирует проверку без отмены
  предыдущего подтверждения цепочки.
- Новый неизвестный блок/непустые новые headers по-прежнему немедленно
  отменяют готовность до проверки. Сохранены expiry 60 секунд, проверка
  совпадения active/header tip и требование наличия готовых пиров.
- Ошибка отдельного пира не отменяет успешную проверку другим. Пир из
  старого снимка списка пропускается, если уже не READY. Закрытие между
  проверкой и запросом дает IOException с точным сообщением и DEBUG,
  вместо misleading handshake stack trace. Ошибки состояния открытого
  пира по-прежнему не скрываются.

Ни window=1024, ни heap=8 GiB, ни размеры кешей, ни пути SSD/HDD не менялись.

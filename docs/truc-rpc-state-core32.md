# TRUC: состояние отказа и порядок проверок

Для наследования версии между v3 и не-v3 добавлен структурированный отказ.
RPC получает Core-описание `TRUC-violation` с txid и wtxid ребёнка и родителя.
Одиночная и пакетная пробы сохраняют индекс индивидуального отказа; общая
TRUC-проверка CPFP возвращает подробную причину всего пакета.

Индивидуальная TRUC-проверка выполняется после проверки минимальной комиссии,
до экономических проверок RBF. Неверная версия теперь не скрывается ошибкой
недостаточной комиссии замены. Для обычной не-v3 транзакции используются
прямые обращения к родителям без обхода всего кластера.

TrucRejectionStateTest проверяет оба направления наследования, приоритет перед
RBF и сохранение результатов общей пакетной фазы. BitcoinCore32CompatibilityTest
сравнивает полные ответы настоящего Core 32.1 для одиночной/пакетной пробы и
submitpackage, включая подписанную замену.

Это не закрывает весь mempool. Бюджетный optimizer, постоянный инкрементальный
граф, полный порядок равных ставок, остальные TRUC-диагностики, полная таблица
скриптовых ошибок и сложные RBF/eviction-сценарии остаются в
[списке работ](mempool-core32-execution.md).

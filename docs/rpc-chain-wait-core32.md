# RPC ожидания активной цепочки

Добавлены `waitfornewblock`, `waitforblock`, `waitforblockheight` по Bitcoin
Core 32.1. Эталон — `src/rpc/blockchain.cpp`; локальная копия находится в
`target/core-update-audit/core32-rpc-blockchain-reference.cpp`.

Ожидание связано с реальными изменениями активной вершины. Поток освобождает
chain monitor на время ожидания; изменения mempool и ложные notify не
удовлетворяют условие. Используется монотонный deadline. Поддерживаются
бессрочное ожидание, timeout, уже выполненное условие, реорганизация и выход
при остановке RPC. `waitforblock` ожидает именно активную вершину, а не любой
известный исторический блок. `waitfornewblock` поддерживает `current_tip`.

Позиционные и именованные аргументы, включая смешанный `args`, поддерживают
те же проверенные ошибки, что Core: число аргументов, JSON type/позиции,
целое int32, отрицательный timeout, hash length/hex, неизвестные имена и
повторное указание позиционного/именованного аргумента. Проверка типов
собирает несколько ошибок до исполнения метода.

Полные OpenRPC-описания и `help` этих трёх методов получены из изолированного
Core 32.1 и сохранены в `app/src/main/resources/rpc/core32-wait-methods.json`.
Это описания работающих методов, а не объявления отсутствующих возможностей.
Остальные RPC пока используют прежние неполные схемы и требуют отдельной
доработки.

`RpcChainWaitTest` проверяет timeout/немедленный ответ, три одновременных
ожидания, ложное пробуждение, реорганизацию на меньшую высоту, исторический
hash и остановку сервера. Отдельный сценарий с управляемыми latch фиксирует запрос между регистрацией
и входом в ожидание и проверяет, что shutdown даёт ему завершить ответ.

`BitcoinCore32CompatibilityTest` сравнивает полные
описания методов, тексты help, 12 успешных вызовов, 25 ошибочных вызовов и
асинхронное ожидание одного и того же нового блока в Core/Java.

Это первый блок RPC-доработки. Недостающие методы, остальные схемы и полная
матрица transport/dispatch/error semantics остаются открытыми.

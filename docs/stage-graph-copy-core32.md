# Изолированное копирование графа для staged-пула

Validation/broadcast probe, пакетный приём и подготовка reorg теперь копируют
готовые entries, spent-index, totalVirtualBytes и граф основного mempool.
Повторное построение этих индексов по inputs всех транзакций при начальном
наполнении staged-пула устранено. Индекс содержит только txid и связи;
объекты транзакций остаются неизменяемыми записями карты entries.

У каждой копии отдельные изменяемые Node.parents/children, Component.members,
карты membership и набор компонент. Разрешено разделять лишь неизменяемые
опубликованные Set/List-снимки. Копирование увеличивает собственную версию
индекса назначения, поэтому замена ранее использованной копии не может
сохранить устаревший кеш с той же версией.

Фильтрация начального набора удаляет только заданные записи. При reorg
подтверждённый родитель удаляется без удаления детей: они могут использовать
его уже подтверждённые выходы. Для package-RBF используется заранее найденное
замыкание конфликтов. Spent-index очищается только для удалённых записей.
Политика копирования rolling fee, unbroadcast и fee delta сохранена отдельно
для каждого существующего пути; внешняя transaction-set sequence не копируется.

Регрессия через публичный testAccept с уже известной транзакцией сначала
воспроизвела вызовы transaction.inputs из rebuildSpent и graph.reconcile:
`target/core-update-audit/core32-stage-graph-copy-red.log`.
После исправления причина отказа txn-already-in-mempool и исходный снимок
сохраняются, повторного чтения inputs нет. Три теста графа проверяют независимые
изменения источника/копии, опубликованные и ещё не опубликованные снимки,
повторное копирование, версию назначения и копирование пустого графа.
Целевой прогон:
`target/core-update-audit/core32-stage-graph-copy-focused.log`.

Это копирование O(V+E) с отдельной изменяемой структурой, а не Core TxGraph
с разделяемым staging и бюджетным оптимизатором. Bulk commit ещё пересобирает
spent-index (этот проход устранён следующим [изменением commit по разнице](spent-commit-delta-core32.md)),
revalidate проверяет транзакции заново; кеш линейзаций не переносится
между пулами. Полный main/staging TxGraph, инкрементальные линейзации и budgeted
spanning-forest solver остаются открытыми.

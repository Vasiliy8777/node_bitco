# Проверки до завершения mainnet-синхронизации — 2026-10-08

Проверки выполнены на локальном Bitcoin Core v31.1.0, Java 21 и RTX 4070.
Основная mainnet-нода оставлена остановленной. Core, Java-нода и GPU-воркер
интеграционных тестов используют временные базы regtest и отдельные локальные
порты. Адрес кошелька из окружения не изменялся; тестовые конфигурации явно
задают выплаты для regtest.

## Найденные и исправленные ошибки

### Отказ обработки настоящих mainnet ADDRv2

Ограниченный адресный probe опросил 12 публичных узлов и получил восемь
сообщений ADDRv2; четыре подключения не дали сообщения. Блоки не запрашивались.
Четыре сообщения по 1000 адресов воспроизвели исходный отказ
`CompactSize value exceeds signed long range`; четыре коротких сообщения прошли.

Причина — поле services содержит полный uint64, включая неизвестный старший
бит. Общий декодер CompactSize ограничивал его положительным signed long.
Исправлены чтение, запись и хранение service flags. Ограничения для количества
элементов и длины сообщений сохранены. Регрессии проверяют каноничность,
старший бит, round trip и сохранение в AddrMan/legacy relay.

После исправления декодер принимает восемь из восьми захваченных сообщений.
Дополнительный тест `CapturedAddrV2ProtocolTest` передаёт те же payloads
непосредственно в `PeerAddressProtocol`, где возникало отключение: **8/8 прошли**.
Это объясняет воспроизведённые отказы, но не заменяет длительное наблюдение
за mainnet-соединениями после возобновления синхронизации.

Правило формата: [BIP155](https://github.com/bitcoin/bips/blob/master/bip-0155.mediawiki).
Артефакты: `target/addrv2-probe-20261008/{manifest.json,replay.log,replay-fixed.log}`.
Повтор: `python tools/addrv2-probe.py`; сохранённые payloads находятся в `.bin`.

### Статистика UTXO и snapshot не учитывали буфер записи

На согласованной высоте 150 состояние Core и Java совпадало. После
`invalidateblock` до 147 tip совпал, а Java RPC всё ещё считал 150 выходов.
Причина — полный RocksDB iterator видел сохранённые данные без write-back
overlay. Точечные обращения к UTXO учитывали overlay; ошибка не доказывает
нарушение проверки spends.

Перед полным подсчётом, статистикой и экспортом snapshot теперь выполняется
`forceFlushChainstate()`. Регрессия проверяет buffered creates/deletes,
сумму, число выходов и содержимое snapshot. Повторная сверка с Core проходит
на исходной высоте, после отката и после восстановления. Обработка каждого
блока не получила дополнительного flush; дорогие диагностические RPC могут
потребовать запись буфера под блокировкой chain, как и сам полный скан.

### GPU продолжал отправлять решения предыдущей высоты

После нахождения network-target решения CUDA-клиент теперь ожидает ответ
и смену задания, прежде чем продолжать. Это устраняет отправку остальных
решений старого шаблона после принятого блока. Обычные shares продолжают
обрабатываться без этого ожидания.

## Выполненные проверки

* Живое сравнение Core/Java: tip, chainwork, raw blocks/headers на выбранных
  высотах, UTXO count, amount и полный `hash_serialized_3`.
* Откат на три блока и восстановление с повторной сверкой состояния.
* 64 попытки мутации merkle root и блок с неизвестным родителем: одинаковое
  отклонение обеими нодами. Это ограниченный набор, а не полный каталог
  отрицательных сценариев; некоторые мутации повторяются.
* Настоящие BIP324 v2-сессии в обоих направлениях Java ↔ Core.
* Реальный CUDA → TCP Stratum → Java validation → P2P → Core путь.
* 15 сценариев принудительного завершения дочернего JVM во время submission,
  spend, disconnect, reconnect и переключения ветки; ещё семь сценариев
  завершения во время работы со snapshot.
* Тесты границ BIP34/65/66, deployment states, Taproot, reorg, invalid blocks,
  storage failures, а также Core-векторы script (1212), sighash (500) и
  transactions (213) из полного Maven reactor.
* Python unit tests и CUDA self-test: 513 хешей, genesis, endian/target,
  границы nonce и переполнение буфера результатов.

В изолированной Java-конфигурации `bitcoin.assume-valid=0`; это полная проверка
именно данной regtest-цепочки, а не историческая перепроверка mainnet.

Итоговый полный Maven reactor: **exit 0, 3964 тестовых случая, 0 failures,
0 errors, 9 skipped**. Из девяти пропусков три — расширенные проверки,
запущенные отдельно, три — performance benchmarks, три — старые интеграционные
тесты, требующие заранее подготовленного Core на порту 18444 с фиксированными
историческими хешами. Живое сравнение в новом тесте использует собственную
временную Core-ноду. Лог: `target/pre-mainnet-final-20261008.log`;
сводка без environment/system properties:
`target/pre-mainnet-20261008/final-reactor-summary.json`.

Отдельный расширенный запуск также завершился **exit 0: 9 тестов,
0 failures/errors/skipped** (`BitcoinCorePreMainnetTest`,
`CapturedAddrV2ProtocolTest`, `StratumIntegrationTest`). Шесть тестов Stratum
повторяют обычный reactor; три ранее пропущенные opt-in проверки выполнены.

## Задержки и ограниченный длительный прогон

Отдельный тест измеряет 60 смен шаблона от изменения backend revision до
получения `mining.notify` по TCP. Итоговый замер: p50 804.44 ms,
p95 963.43 ms, p99/max 976.88 ms. Сервер проверяет шаблон раз в секунду;
для меньшей задержки потребуется уведомление при смене tip/mempool.

Длительный тест успешно завершил **600 последовательных CUDA-блоков**,
Java/Core достигли высоты 750, начиная со 150. Длительность теста 608.408 s,
без errors/failures. Core принял все 600 блоков; число наблюдений — 600.
Повторный сертификат после майнинга подтвердил одинаковые tip, chainwork,
UTXO count/amount/`hash_serialized_3`, откат 750 → 747 и восстановление 750.
Для каждого наблюдаемого нового tip тест проверял принятие блока Core;
после прогона повторил сверку UTXO и откат/восстановление. Пассивный наблюдатель отправляет
запрос раз в 60 высот, чтобы не попадать под inbound idle timeout 180 s.
Активный GPU-клиент отправляет submit регулярно.

`latency.txt` содержит время от обнаружения Java tip до ответа Core CLI и
последующего чтения notify. Это наблюдаемая верхняя оценка с затратами на
запуск CLI и последовательное измерение, а не чистая задержка сети или
независимый замер notify. Точный замер notify находится в отдельном файле.

Наблюдаемые времена с Core CLI: p50 96.50 ms, p95 134.69 ms,
p99 177.15 ms, max 308.41 ms. Последующее чтение notify: p50 998.57 ms,
p95 1008.32 ms, p99 1011.85 ms, max 1106.02 ms. Значения включают
описанные выше накладные расходы. Основной лог расширенного запуска:
`target/pre-mainnet-live-final-20261008.log`; GPU:
`target/pre-mainnet-20261008/gpu-soak.log`.

Дополнительно выполнен непрерывный SHA256d benchmark длительностью 60 s:
**1623.92 MH/s**, exit 0, stderr пуст. На фоне этого прогона продолжал
работать regtest GPU-воркер. Измеренные пики по `nvidia-smi`: 62 °C,
128.99 W, GPU utilization 64%. Это минутная проверка вычислений и драйвера,
а не многочасовой thermal/stability test и не доказательство полной загрузки
всех ресурсов GPU. Артефакты: `gpu-load.log`, `gpu-load-error.log`,
`gpu-telemetry.csv` в `target/pre-mainnet-20261008`.

## Воспроизведение

Полный reactor с установленным Core и CUDA:

```powershell
.\mvnw.cmd -q test '-Dbitcoin.core.binary=C:/Program Files/Bitcoin/daemon/bitcoind.exe' '-Dbitcoin.gpu.test=true'
```

Расширенные локальные проверки, включая ограниченный GPU-прогон:

```powershell
.\mvnw.cmd -q -pl app -am test '-Dtest=CapturedAddrV2ProtocolTest,StratumIntegrationTest,BitcoinCorePreMainnetTest' '-Dsurefire.failIfNoSpecifiedTests=false' '-Dbitcoin.pre-mainnet.test=true' '-Dbitcoin.pre-mainnet.blocks=600'
```

По умолчанию расширенные тесты выключены; captured replay дополнительно
требует payloads из probe. Обычный Core binary/GPU opt-in не включает soak.
Скрипты сертификатов запускаются с process-only ExecutionPolicy Bypass;
политика PowerShell системы не меняется.

После завершения проверено отсутствие тестовых Core/GPU-процессов,
старых PID основной ноды/воркера и listeners на 8332/8333/3333.
`git diff --check` прошёл.

## Что остаётся после синхронизации

Сверка основной mainnet-базы на согласованных высотах, полная историческая
проверка с `--bitcoin.assume-valid=0`, многочасовая работа на реальной сети,
mainnet block relay под нагрузкой и подключение конкретного ASIC остаются
непроверенными. Принудительное завершение процесса не моделирует отключение
питания диска. Regtest GPU-прогон проверяет контур и смену заданий, но не
длительную работу GPU на полной вычислительной нагрузке.

Результаты локальных проверок не означают доказанное соответствие всем
правилам, политикам и консенсусу Bitcoin Core на всей mainnet-истории.

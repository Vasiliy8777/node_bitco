# Mempool и пакетный приём: объём завершения

Эталон — фиксированный Bitcoin Core 32.1. Успешная сборка не закрывает все
следующие требования; каждый пункт требует реализации и независимых сценариев.

| Область | Статус |
| --- | --- |
| Бюджетный spanning-forest optimizer | Открыто: production всё ещё использует exact maximum-closure solver; нужны бюджет, продолжение работы, fallback и независимые векторы. |
| Постоянный инкрементальный граф | Открыто: spent index используется локально, но нет полного TxGraph с main/staging, инкрементальными компонентами и линейзациями. |
| Равные ставки | Открыто: порядок и fallback Core ещё не воспроизведены во всех сценариях. |
| Общая фаза пакетной пробы | Предварительные проверки отделены от скриптов; в текущем изменении TRUC пакета, cluster limits и ephemeral-spends перенесены в общую фазу. Индивидуальная TRUC-проверка видит исходный mempool. Полное совпадение диагностики и всех приоритетов ещё не доказано. |
| Скриптовые отказы пробы | Частично: структурированный отказ, успешный префикс, незавершённый суффикс, maxfeerate и подробности входа реализованы; witness v0 и ряд interpreter-ошибок передают описания Core. Полная таблица legacy/P2SH/Taproot/tapscript/opcodes ещё открыта. [Реализация и проверки](package-script-results-core32.md). |
| Частичный submitpackage | Частично: индивидуальный приём, сохранение успешных родителей, per-tx results и общая фаза CPFP перед скриптами реализованы. Полная диагностика, отдельные TRUC/client cap/RBF приоритеты и сложные RBF/eviction-сценарии открыты. [Частичный приём](submitpackage-partial-core32.md), [общая фаза](shared-submission-phase-core32.md). |
| Клиентские лимиты submitpackage | Известные записи освобождены от повторного maxfeerate; новые проверяются внутри admission по усечённому modified-feerate без переполнения произведения. Burn проверяется по выходам до приёма. Полная матрица fee deltas/TRUC/ephemeral ещё открыта. |
| Метаданные комиссий | Новые индивидуальные/CPFP-записи получают effective-feerate/effective-includes; известные — только base. Базовые пути проверены с Core; сложные RBF/eviction-сценарии ещё открыты. |

Текущая реализация и проверки общей фазы:
[package-shared-policy-phase-core32.md](package-shared-policy-phase-core32.md).

Дополнение: точная диагностика наследования TRUC, индекс отказа и приоритет
перед экономическими проверками RBF подтверждены сравнением полных ответов
нативного Core; [сценарии и оставшийся объём](truc-rpc-state-core32.md).
Три первые строки таблицы этим дополнением не закрыты.

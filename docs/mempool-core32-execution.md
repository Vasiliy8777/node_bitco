# Mempool и пакетный приём: текущая приёмка

Актуальная реализация 13 ноября 2026: перечисленные восемь подпунктов реализованы
и сопоставлены с Core 32.1. Итоговая упаковка/рабочий запуск и точные границы
свидетельств фиксируются в [отчёте приёмки](mempool-core32-completion.md).

| Область | Реализация и независимые свидетельства |
| --- | --- |
| Бюджетный optimizer | SFL, CostModel, PostLinearize, genuine seeded RNG, 75000/375000, продолжение и quality states; 9600 точных C++ векторов. |
| Постоянный main/staging граф | Разделяемые неизменяемые узлы/компоненты/модели, инкрементальные порядки и публикация по дельте; 3600 снимков Core, 383 пары RBF-диаграмм. |
| Равные ставки | Единый Core mining key, обратный eviction key, prefix weight и serialized txid; нативное переполнение с 1100 пакетами. |
| Общая фаза пробы | Отдельные SingleTRUCChecks/PackageTRUCChecks, cluster и ephemeral проверки до скриптов, исходный mempool для индивидуальных проверок; проверены приоритеты и package/per-tx отказы. |
| Скриптовые отказы | Типизированы 55 ScriptError; 1237 исходных векторов сверяют точный код, расширенная матрица содержит legacy/P2SH/witness/Taproot/tapscript и подробности входа. |
| Частичный submitpackage | Отдельный приём родителей, сохранение успешных записей, CPFP retry, правильная публикация memory eviction и только RBF в replaced-transactions. |
| Клиентские лимиты | Новые/известные записи, maxfeerate/burn и fee deltas; ранний отказ не запускает expiry, probe не выполняет memory trim. |
| Метаданные комиссий | Effective-feerate/effective-includes для новых записей, base для известных, сохранённый witness; полные ответы сопоставлены с Core. |

Дополнительно перенесены оценка памяти Core, historical randomized capacity,
rolling-fee decay, индексированная expiry и TxGraph::Trim. Проверены 512
независимых trim-сценариев и настоящий reorg 72 → 64 с одинаковыми записями.

## История промежуточного объёма

Ниже сохранён прежний аудит этапов. Указанные в нём открытые mempool-пункты
относятся к состоянию до реализации и проверок, описанных выше.

Эталон — фиксированный Bitcoin Core 32.1. Успешная сборка не закрывает все
следующие требования; каждый пункт требует реализации и независимых сценариев.

| Область | Статус |
| --- | --- |
| Бюджетный spanning-forest optimizer | Открыто: production всё ещё использует exact maximum-closure solver; нужны бюджет, продолжение работы, fallback и независимые векторы. |
| Постоянный инкрементальный граф | Частично: постоянные parent/child-связи и компоненты основного пула, индексированное удаление потомков и кеш по версии реализованы. Bulk commit обновляет индекс по разнице; начальное наполнение staged-пула копирует готовые индексы без обхода inputs. Полный Core main/staging TxGraph с разделяемой структурой и инкрементальные линейзации открыты. [Основной индекс](persistent-main-graph-core32.md), [bulk commit](graph-commit-delta-core32.md), [staged copy](stage-graph-copy-core32.md). |
| Равные ставки | Исправлены проверенные ключи графа/майнинга и обратный comparator eviction: equal-rate prefix weight, maximum chunk txid и serialized txid order. Нативная pressure-eviction, budgeted/staging и полная mutation-матрица остаются открытыми. [Порядок](equal-rate-fallback-core32.md), [eviction](equal-rate-eviction-core32.md). |
| Общая фаза пакетной пробы | Предварительные проверки отделены от скриптов; в текущем изменении TRUC пакета, cluster limits и ephemeral-spends перенесены в общую фазу. Индивидуальная TRUC-проверка видит исходный mempool. Полное совпадение диагностики и всех приоритетов ещё не доказано. |
| Скриптовые отказы пробы | Частично: структурированный отказ, успешный префикс, незавершённый суффикс, maxfeerate и подробности входа реализованы; witness v0 и ряд interpreter-ошибок передают описания Core. Полная таблица legacy/P2SH/Taproot/tapscript/opcodes ещё открыта. [Реализация и проверки](package-script-results-core32.md). |
| Частичный submitpackage | Частично: индивидуальный приём, сохранение успешных родителей, per-tx results и общая фаза CPFP перед скриптами реализованы. Полная диагностика, отдельные TRUC/client cap/RBF приоритеты и сложные RBF/eviction-сценарии открыты. [Частичный приём](submitpackage-partial-core32.md), [общая фаза](shared-submission-phase-core32.md). |
| Клиентские лимиты submitpackage | Известные записи освобождены от повторного maxfeerate; новые проверяются внутри admission по усечённому modified-feerate без переполнения произведения. Burn проверяется по выходам до приёма. Полная матрица fee deltas/TRUC/ephemeral ещё открыта. |
| Метаданные комиссий | Новые индивидуальные/CPFP-записи получают effective-feerate/effective-includes; известные — только base. Базовые пути проверены с Core; сложные RBF/eviction-сценарии ещё открыты. |

Текущая реализация и проверки общей фазы:
[package-shared-policy-phase-core32.md](package-shared-policy-phase-core32.md).

Дополнение: точная диагностика наследования TRUC, индекс отказа и приоритет
перед экономическими проверками RBF подтверждены сравнением полных ответов
нативного Core; [сценарии и оставшийся объём](truc-rpc-state-core32.md).
Три первые строки таблицы этим дополнением не закрыты.

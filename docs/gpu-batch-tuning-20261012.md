# Размер CUDA-пакета на RTX 4070

## Методика

Нода штатно остановлена, чтобы действующий майнер не конкурировал с
бенчмарком. Использован настоящий CudaHasher.search с target=0, тем же
kernel, передачей данных и синхронизацией CUDA, что в майнинге.
Перед измерениями GPU self-test подтвердил 513 хешей, включая genesis,
endian/target, границу nonce и переполнение результатов.

Два прохода четырех размеров: сначала по возрастанию, затем по убыванию.
Каждый вариант: 2 с прогрева + 8 с измерения. Телеметрия nvidia-smi раз в
секунду. Это короткий замер конкретной RTX 4070, а не универсальная настройка
для всех видеокарт. Отдельная нода не работала параллельно с бенчмарком.
Данные: target/gpu-batch-benchmark.json и target/gpu-batch-benchmark.log.

| Batch | Средний MH/s | Диапазон двух проходов | Средний P95 вызова, мс |
|---:|---:|---:|---:|
| 262144 | 1670,8 | 1667,8—1673,9 | 0,20 |
| 524288 | 2022,8 | 1986,0—2059,6 | 0,33 |
| 1048576 | 2445,1 | 2405,9—2484,2 | 0,57 |
| 2097152 | 2686,5 | 2662,8—2710,2 | 1,00 |

Последний вариант быстрее базового примерно на 61% в одинаковом benchmark,
и на 10% быстрее 1048576. Его P99 около 1,29 мс; типичный пакет не создает
большой задержки переключения задания. Однако в некоторых вариантах были
редкие выбросы до 173 мс: P95 не является максимальной задержкой.
Процент занятости GPU у 2097152 около 87—91%, температура 70—73 C,
потребление около 178—179 W в benchmark.

## Применение

Добавлен bitcoin.gpu-miner.batch-size, передаваемый Spring-владельцем
процесса как --batch-size. В application-gpu.yml установлено
`${BITCOIN_GPU_BATCH_SIZE:2097152}`. Переменная позволяет менять размер.
Предел CLI расширен до 2097152; штатный размер standalone CLI остался
262144. Проверка диапазона также выполняется до запуска дочернего процесса.
Старый конструктор GpuMinerProcess сохранен с прежним размером.

Четыре Python unit-теста и три JVM-теста прошли. Проверены точная передача
2097152, владение/остановка процесса и запуск настоящего CUDA worker через
Spring с генерируемым паролем. Лог: target/gpu-batch-config-tests.log.
git diff --check пройден. Частоты, напряжение и power limit не менялись.

## Настоящий майнинг

Запущен PID 57932 с профилями mainnet,gpu. Применение размера проверено
логом CUDA worker started и аргументами дочернего процесса.
Нода синхронизирована: blocks=headers=971028, initialblockdownload=false.
GPU принимает shares; к 09:55:26 реальный хешрейт 2488 MH/s против прежних
примерно 1400—1450 MH/s: прирост около 72—78%. Прирост benchmark и live
не тождественны: live также обрабатывает задания, Stratum и переключения.
Телеметрия live: загрузка 84%, 72 C, 172,45 W.

Нода оставлена запущенной с 2097152 — лучшим из четырех проверенных вариантов.
Короткий замер не позволяет оценить долгосрочный процент Stale job; p95/p99
пакета и работа реального майнинга подтверждены, окончательный оптимум CUDA-ядра
за пределами этих размеров не исследовался.

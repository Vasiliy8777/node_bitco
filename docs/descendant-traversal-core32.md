# Обход потомков без повторного сканирования mempool

Эталон: [Core 32.1 CalculateDescendants и removeRecursive](https://github.com/bitcoin/bitcoin/blob/v32.1/src/txmempool.cpp#L282)
получают потомков через связи TxGraph, включая удаление потомков транзакции,
которая сама отсутствует в пуле после reorg.

В MempoolGraphPolicy.descendants прежний fixed-point алгоритм повторно
сканировал все записи, пока находились новые потомки. Цепочка, записанная
в обратном порядке, требовала отдельного прохода на каждый уровень.
Теперь связи parent → children строятся один раз, после чего очередь посещает
каждого найденного потомка один раз. Стоимость одного вызова O(V+E), память
O(V+E); пустой набор корней не читает пул.

Сохраняются включение самих корней, поиск детей отсутствующего корня,
объединение пересекающихся ветвей и независимость от порядка записей.
Исправление используется при RBF, package-RBF, рекурсивном удалении,
TRUC-проверках и RPC-получении потомков. Набор принятых транзакций этим
изменением намеренно не меняется.

DescendantTraversalWorkTest проверяет:

- 300 случайных DAG с перемешанным порядком против независимого fixed-point
  расчёта, с несколькими и отсутствующими в пуле корнями;
- обратную цепочку из 10 000 записей с бюджетом ровно одного чтения каждой
  записи вместо проверки по нестабильному времени выполнения;
- отсутствующий корень и повторную ссылку на него;
- отсутствие чтений при пустых корнях.

нескольких последовательных запросов не объявляется равной Core.

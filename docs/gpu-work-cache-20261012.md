# Кеш подготовки CUDA-задания

## Изменение

В miner.py coinbase, Merkle root, заголовок и строка extranonce2 больше
не вычисляются перед каждым пакетом nonce. Они сохраняются до изменения
материала задания или перехода nonce через 2^32. Цели сложности вычисляются
при получении нового задания. Для проверки найденного решения сохранен
76-байтовый префикс заголовка; nonce каждого решения по-прежнему добавляется
отдельно и проверяется SHA256d на CPU.

Изменение родителя, coinbase, Merkle branches, версии, bits, времени,
extranonce1 или размера extranonce2 обновляет заголовок. Новая wire-id
того же материала не вызывает повторный расчет заголовка и не сбрасывает
nonce; новый job id используется при отправке результата. Сложность shares
применяется к следующему mining.notify, как и раньше, обновляя target.
Новый extranonce2 всегда меняет coinbase/Merkle root и пересчитывает заголовок.

CUDA backend уже кешировал SHA-256 midstate заголовка, но передавал target
на GPU при каждом пакете. Теперь неизменная цель также кешируется; меняется
и передается при изменении значения. Hashing без target этот кеш не портит.
Сетевые уведомления по-прежнему проверяются между пакетами. Отмена результатов
устаревшего поколения и FOUND BLOCK сохранены. Batch остается 2097152.

## Проверка

10 Python-тестов прошли. Проверены:

- повторное использование данных и непрерывное продвижение nonce;
- полный rollover nonce с пересчетом Merkle root для extranonce2=1;
- изменение времени, версии, bits, родителя и Merkle branch;
- обновление wire-id и сложности без пересчета неизменного заголовка;
- изменение extranonce1/размера extranonce2;
- передача target только при его изменении;
- существующие проверки endian, Merkle и сложности Stratum.

На настоящей GPU self-test подтвердил 513 хешей, genesis, сравнение target,
границу nonce и переполнение результата. git diff --check пройден.

## Производительность и запуск

При остановленной ноде выполнены четыре коротких прохода old/cached/cached/old
с настоящим CudaHasher.search, batch=2097152, фиксированным заданием с
12 Merkle branches: 2 с прогрева и 8 с измерения на проход.
Old воспроизводит подготовку на каждый пакет и передачу цели; cached
обновляет данные по rollover. Target поиска в обоих случаях 0, без отправки shares.

Результаты MH/s: old 2345,4 и 2598,6; cached 2532,0 и 2731,6.
Средние: около 2472 против 2632 MH/s, примерно +6,5%.
Разброс между проходами существенный: это ориентир, а не гарантированный
процент прироста реального майнинга. Данные:
target/gpu-work-cache-benchmark.json и target/gpu-work-cache-benchmark.log.

Предыдущий PID 63592 штатно остановлен; до остановки около 2484 MH/s.
Запущена обновленная нода PID 51348, блоки и заголовки 971086,
initialblockdownload=false, GPU принимает shares. Первые live-показания
около 2534 MH/s; позже показания колебались примерно от 2156 до 2561 MH/s.
По этому live-интервалу устойчивый прирост не подтвержден; для его оценки
требуется более длинное сравнение при одинаковой нагрузке ноды.
Данные запуска: target/gpu-work-cache-live-20261012.jsonl.
Нода оставлена работающей.

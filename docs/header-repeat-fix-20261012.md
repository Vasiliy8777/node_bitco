# Повтор известного заголовка завершал live sync

## Событие

В 08:14:41 PID 52684 перешел RUNNING -> FAILED:
`IllegalStateException: Non-empty headers response made no synchronization progress`
в HeaderSyncCoordinator.synchronize:125. Последний обработанный hash совпал
с локальным курсором. После остановки live sync GPU оставалась idle до исправления.

HEADERS не содержит идентификатора запроса. Повтор уже известного tip или
unsolicited-объявление может попасть в ожидание GETHEADERS; наличие непустого
ответа само по себе не гарантирует новую высоту. Конкретный источник повторного
пакета старый лог не фиксирует, но фатальный переход на равенстве hash подтвержден.

## Изменение

Полностью валидированный пакет, заканчивающийся текущим курсором, теперь
завершает раунд без ошибки. Повтор не публикуется как новая batch; ранее
полученные новые заголовки сохраняются. Проверки HeaderSyncService выполняются
перед этим решением. Внутренний сбой с пустым результатом непустой batch
по-прежнему не скрывается.

Цикл ответов A -> B -> A выявляется набором посещенных batch-tip hash и дает
IOException: ошибка пира обрабатывается failover, а не завершает всю ноду.

В старом логе были также ожидания GETHEADERS по PT2M. Live polling теперь
ограничен пятью секундами на ответ, сохраняя меньший настроенный таймаут;
таймаут первичной синхронизации заголовков не меняется. Это позволяет быстрее
переключаться со слишком медленного пира при сроке freshness 60 секунд.

Heap, окно блоков, кеши и пути SSD/HDD сохранены.

цикл ответов, streaming, HeaderSyncCoordinator, live sync и lifecycle.

поведение: раунд завершается, дубликат не публикуется. git diff --check пройден.

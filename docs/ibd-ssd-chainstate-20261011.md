# Chainstate на SSD, архив блоков на HDD

## Реализация

Добавлено свойство `bitcoin.chainstate-directory`: независимый корневой
каталог для `<network>/chainstate`. Пустое значение сохраняет прежнее размещение.
`bitcoin.data-directory` продолжает задавать путь к блокам, undo и данным пиров.
RocksDbDatabase принимает отдельный корень файловых данных; ссылки на позиции
блоков и undo остаются в той же атомарной RocksDB-базе, формат данных не изменен.

Если старая база существует, а в новом каталоге нет CURRENT, запуск отклоняется
с требованием предварительно скопировать chainstate при остановленной ноде.

В GPU-конфигурации запуска и локальной конфигурации IntelliJ установлен
`-Dbitcoin.chainstate-directory=data/ssd-chainstate`.
Путь вычисляется относительно рабочей директории проекта.
Альтернативная настройка для mainnet: переменная `BITCOIN_CHAINSTATE_DIRECTORY`.

Фактические пути:

- SSD C: (HP SSD FX900 Pro 1TB):
  `C:/Users/Vasiliy/IdeaProjects/bitcoin-node/data/ssd-chainstate/mainnet/chainstate`.
- HDD K: (WDC WD60EZAZ): `K:/BitcoinJavaNode/mainnet/blocks`.
- Неизмененная резервная копия на момент остановки:
  `K:/BitcoinJavaNode/mainnet/chainstate`.

Каталог data исключен из Git; содержит постоянную рабочую базу, а не временные
результаты сборки. Архив целиком на SSD не переносился. Окно осталось 1024,
Java heap 8 GiB, native cache 4 GiB, кеш UTXO 1 000 000 записей;
prefetch по-прежнему отключен.

В этом замере общая скорость выше примерно в 11 раз, обработка блока —
примерно в 28 раз, средняя задержка логического чтения — примерно в 53 раза.
Это сравнение последовательных участков цепочки, а не повтор одного набора
блоков: отличаются транзакции, кеши и пиры. Показатель get включает пути,
которые обслуживаются кешем, и не является чистой задержкой физического SSD.
Данные расчета: `target/ibd-ssd-comparison.json`.

В первые минуты регулярно frontierAvailable=false: следующий нужный блок
еще не скачан, хотя более поздние блоки доступны. После ускорения базы
появилось заметное ожидание скачивания. Параметры сети не менялись.

В 10:03 jstat: Full GC=0, суммарное время GC 2,720 с. Нет подтверждения
длительной устойчивости по короткому замеру. Нода оставлена запущенной.

## Дальнейшие запуски и возврат

Запускать GPU-конфигурацию с указанным свойством пути. Новые изменения
chainstate записываются только на SSD; оставшаяся база на HDD уже устаревает.
Для возврата на HDD нужно штатно остановить ноду и перенести актуальную базу
с SSD, затем убрать свойство отдельного пути. Простое переключение на старую
резервную копию не сохраняет последующий прогресс.

# Инкрементальное обновление графа при общем commit

После предыдущего изменения обычные добавления и удаления уже поддерживали
постоянный индекс, но RBF/package/revalidate/reorg повторно строили его целиком.
Теперь общий commit использует `MempoolGraphIndex.reconcile`: удаляет исчезнувшие
txid, сохраняет существующие связи и компоненты, добавляет новые вершины.
Inputs существующих транзакций индекс не читает: txid фиксирует зависимости.
Новые связи с существующими детьми находятся через финальный spent-index.
Это поддерживает произвольный порядок новых вершин и возвращение родителя
после уже присутствующего ребёнка.

Незатронутые компоненты сохраняют идентичность опубликованных снимков. После
commit версия комиссий инвалидируется даже при неизменном составе пула:
modified fee и sigops могут измениться без изменения txid. Кеш проверяет
обновлённые оценки, а неизменные кластеры не требуют повторной линейзации.

Три новые проверки в MempoolGraphIndexTest:

- Карта запрещает чтение значений существующих записей; добавление ребёнка
  сохраняет снимок независимой компоненты. Commit только с fee delta меняет
  версию и сохраняет компоненты.
- Обратный порядок child/grandchild, поздний parent и удаление промежуточного
  child дают ожидаемые связи и разделение компонент.
- 200 случайных наборов, порядков и fee delta сравниваются с полной пересборкой,
  обходом потомков и некешированной диаграммой комиссий.

Граница реализации: spent-index и карта entries при bulk commit ещё

готового индекса в staged-пул](stage-graph-copy-core32.md), устранив начальное
построение по inputs. Полный main/staging TxGraph, инкрементальные линейзации
и бюджетный оптимизатор Core ещё открыты. Это устранение повторного полного построения
основного графа после commit, не реализация полного Core TxGraph.
